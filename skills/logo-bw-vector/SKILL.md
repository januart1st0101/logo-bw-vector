# Logo修復與轉黑白向量檔

將參考圖片整理為白底黑色的可編輯 SVG，保留字形、筆畫、圖案比例與配置。預設使用繁體中文溝通。

## 先確認原圖

- 先實際檢視原圖；現有對話中的文字確認與配色偏好沿用，不重複詢問。
- 人名、店名、電話與小字逐項核對。若看不清，先詢問不確定的文字，同時繼續不依賴答案的修復工作；確認前不把猜測當定稿。
- 文字內容正確和字形忠實是兩件事：不可自行用一般字體取代書法字、手寫字或品牌字形。若確實需要重排字，先讓使用者知道並取得同意。

## 固定處理順序

1. **原圖放大修復。** 使用可用的內建 imagegen 圖像編輯工具；依環境載入 imagegen 技能。明確標示原圖是編輯目標，要求清理模糊、保留原色、配置、比例、字形、筆畫及細線。目標邊長約 1200–2400px，以工具實際輸出為準。保存彩色修復版，再與原圖對照。放大不保證找回真實細節，尤其不能把 AI 補出的字當成文字證據。
2. **由放大版轉黑白。** 白底、實心黑色 Logo 與黑色文字為預設；使用者指定白底黑邊時改為輪廓版。原本白字要轉黑字，不可因去底而消失。若像信義房屋一樣是白色標誌印在色底上，可將原白色前景轉黑、色底轉白，保留方框與細線；不要無意中合併不同區塊。複雜彩色圖案可另用 imagegen 製作黑白版，重新聲明已確認的全文與字形限制。簡單純色 Logo 可直接分離前景建立黑白遮罩以供向量描摹。保存黑白點陣中間檔。
3. **由黑白版描摹 SVG。** 使用真正的 path/曲線，文字也沿圖形描摹，不以重新輸入字體替代。不得只把 PNG 嵌入 SVG 或改副檔名。可用下方腳本；對已具備品質良好的原生 SVG，直接編輯其路徑即可，不必走影像重製。
4. **由最終 SVG 輸出 PNG 並檢視。** 同時看整張預覽及文字、框線、細節的放大局部。確認人名、店名、電話、比例與筆畫，保留孔洞、細線、矩形直角與鏈條交疊。若黑白版已錯，回到上游修正，不能只提高 PNG 輸出尺寸掩蓋問題。

修復提示詞核心可採：「先放大修復這張原圖，保留配置、比例與原字形；文字逐字為……。不要重設計、改字、換字體或加元素。」黑白階段再指定「白底黑色，保留筆畫與留白」。每次工具輸出都要檢查，不將生成結果直接視為忠實原稿。

## 向量描摹助手

`scripts/trace_bw.py` 只接收已核對的黑字白底圖，依亮度描摹；不是彩色去底、OCR 或影像修復工具。需要 Python、Pillow、NumPy。使用環境提供的依賴定位工具尋找可用 Python，不硬編某一版 runtime 路徑。

```sh
python scripts/trace_bw.py input-bw.png output.svg --threshold 145 --simplify 0.65 --min-area 3
```

- `threshold`：低於此亮度是黑色前景。先看黑白來源再調整，避免細筆畫斷裂或孔洞黏住。
- `simplify`：單位是來源像素，常用 0.4–1.0；越大越容易損失文字細節。
- `min-area`：去除小輪廓的面積門檻；有小字或細小孔洞時不要設太高。
- 可選 `--mask-output mask.png` 保存實際描摹遮罩。
- 以環境中的 SVG renderer（例如 bundled Sharp）輸出 PNG。只有渲染 SVG 後才聲稱交付圖與向量一致。

描摹必須處理對角接觸點的多條邊，不能用單一頂點對應覆寫邊而形成開放輪廓。矩形與長直線要保留，不能把每一邊的中點一律接成二次曲線，否則方框會變成圓形。腳本對這兩點已作處理。

## 保存與交付

- 尊重使用者指定的儲存位置與工作區規則。在允許寫入的工作區新增 `<品牌名>_黑白向量預覽`；既有版本另存 `放大後重製_v2` 等，不覆蓋原稿。未指定位置時使用目前專案的交付目錄；不自行操作歸檔。
- 預設交付：`01_原圖放大修復.png`、`02_放大後轉黑白.png`、`03_<品牌名>_白底黑色.svg`、`04_<品牌名>_白底黑色_2400px.png`、適合聊天顯示的預覽 PNG。2400px 是最終 SVG 渲染尺寸，不能描述成原圖原生解析度。
- 確認 SVG 可解析、沒有嵌入點陣圖、需要獨立交付時不依賴未安裝字體；再檢視渲染結果。
- 最後提供 SVG、PNG 與資料夾的可點擊絕對路徑，直接顯示黑白預覽。簡短說明採用的流程；若有 AI 修復推估或經同意的重排字，據實標示。
